# E2E and chaos results, 2026-11-19

Live runs of `E2E-RUBRIC.md` (E1 to E9) and the live-capable cases of `CHAOS-RUBRIC.md`, on real pi agents started through Paseo.

- Commit under test: `aa41f80` (branch `feat/continue-in-place`, on top of `844e684`). pcg loaded from the working tree through a `packages` entry.
- Model: `deepseek/deepseek-flash` (DeepSeek V4.1 Flash), thinking off. pi 1.5.0.
- Total spend: about $0.11 (301 requests, at the real DeepSeek prices: input 0.3, cache read 0.006, output 1.2 per MTok). Budget was $1.00.
- Test root: `/tmp/pcg-e2e-20261119-1209` (projects `proj`, `proj-roll`, agent dir `agent`).

## Setup, and where it had to differ from the rubric

1. **Agent dir.** `cacheWarming: "idle"` is read from global settings only, and `modelOverrides` (cost, `promptCache`) live in `models.json`, which is also agent-dir only. Neither can be set per project. So the agents ran with `PI_CODING_AGENT_DIR=/tmp/pcg-e2e-20261119-1209/agent` (a scratch agent dir with its own `settings.json`, `models.json`, copied credentials and a `packages` entry for pcg), passed with `paseo run --env`. The owner's `~/.pi` was only read. Project-local: `proj/.pi/settings.json`, `proj/.pi/extensions/` (copies of `dirty-repo-guard.ts` and `confirm-destructive.ts`, plus `zz-cancel.ts`, see below).
2. **Project trust.** Paseo drives pi in RPC mode, which cannot show the trust prompt. With the default `defaultProjectTrust: "ask"` pi silently skips project settings and project extensions (observed: the project `rolloverTokens` was ignored). The scratch agent dir sets `defaultProjectTrust: "always"`.
3. **Prices.** `pricesOf()` takes the model's catalog cost whenever all four fields are finite numbers (`cacheWrite: 0` counts as finite), so `governor.prices` is ignored for this model. Break-even for the real prices is about 20K tokens, not a few thousand. The model override was therefore `cost {input 3, output 0.1, cacheRead 0.006, cacheWrite 0}` plus a `tiers` entry (`inputTokensAbove 1000`, real prices with cacheRead 0.2) so pi's own warming economics (`warmCost`, `missCost`) said "stop" at once while pcg's `checkpointPays` held at about 1.5K tokens. `promptCache.short = 60`. Spend was computed from tokens at the real prices, not from these recorded costs.
4. **Slash commands.** Paseo sends `/governor` and `/new` to the model as plain text, not as commands. So `/governor` output and the `/new` guard proof in E1 could not be observed.
5. **Staging checkpoints.** The idle checkpoint never started under Paseo (see E2). Checkpoints were staged through rollover instead: `rolloverTokens 6000`, and a project extension `zz-cancel.ts` that returns `{cancel: true}` from `session_before_compact` while a flag file exists. With the flag on, the rollover compaction is cancelled, pcg falls back to `newSession`, the guard shows "Clear session?", the answer "No" keeps the session and pcg reopens the checkpoint (`open: true`). With the flag removed and the cache expired (more than 60 s), the next message gets pcg's card. `compaction.keepRecentTokens` was set to 500: with pi's default (20000) a context below 20K tokens makes `ctx.compact` fail with "Nothing to compact (session too small)", so every in-place continue in these small sessions fell back to `newSession` (this is a finding, see below).
6. **Sending messages.** `paseo send` by default interrupts a running turn, which also cancels a pending pcg card. Cases with a second message used the MCP `send_agent_prompt` with `activeTurnBehavior: steer`.

## Findings

1. **In-place continue needs a context above `compaction.keepRecentTokens` (default 20000).** pi's `ctx.compact` refuses with "Nothing to compact (session too small)" before `session_before_compact` runs, so pcg's handler never gets to supply the handoff. For contexts below about 20K tokens, "Continue from checkpoint" and rollover fall back to `newSession` and the two guard dialogs fire. Repro: default settings, a session of about 13K tokens with an open checkpoint, return after the cache expired, choose continue. Real checkpoints pay at much larger contexts at real prices, so this mostly matters for small-model and test setups, but a floor check (or lowering `keepRecentTokens` for the call) would avoid the fallback. In the cancelled/failed case the "Clear session?" dialog is the first one shown and "No" there short-circuits the dirty-repo dialog.
2. **Idle checkpoint does not start under Paseo (E2).** Not resolved, see the E2 row. Only `cache_warming_decision` drives the idle checkpoint.
3. **`paseo send` while a card is open cancels the card** and the second message is not delivered (Paseo behaviour; with steer through MCP pcg holds and delivers it).
4. **Double `paseo send` wedged an agent** (C10 first attempt), recovery only by reloading the pi process. pcg's `select` calls have no timeout.
5. **Empty assistant messages** (`in=0 out=0`, content `[]`) are left in the session when a message interrupts a checkpoint turn; harmless here.
6. `pricesOf()` precedence: the model's catalog cost wins over `governor.prices` whenever all four fields are finite. Tests that rely on `governor.prices` for a model that has complete catalog costs will not see their prices applied.
